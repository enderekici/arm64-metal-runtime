# A64 encoding and execution inventory

The static inventory takes an Arm A-profile machine-readable release, enumerates its A64 instruction records, and sends concrete 32-bit words through this revision’s process decoder. The execution probes exercise selected, explicitly written instructions on native Apple Silicon and both Metal launch configurations. Neither tool changes the runtime.

## Static inventory

From the repository root on Apple Silicon macOS, download Arm’s open 2026-09 package once. The archive SHA-256 is `d5bf3f538663fb18be081ba8e9f08b188ed06f81dd19d4aa2da5b2795103a4ec`. The extracted `Instructions.json` SHA-256 is `ef75f3ec02df1b9b9c0612f4ea259d6710ac3de686b097d8f9c83d1d97aa800a`. [Arm package](https://developer.arm.com/-/cdn-downloads/permalink/Exploration-Tools-OS-Machine-Readable-Data/AARCHMRS_BSD/AARCHMRS_OPENSOURCE_A_profile_FAT-2026-09.tar.gz) · [Arm’s guide to the machine-readable specification](https://developer.arm.com/community/arm-community-blogs/b/architectures-and-processors-blog/posts/working-with-mrs-data)

```sh
python3 tools/inventory/a64_encodings.py --spec /path/to/Instructions.json \
  --fixture-corpus --output /tmp/a64-static.json /bin/cat /usr/bin/cksum /usr/bin/tar
```

Each row retains the Arm record name, group, fixed-bit mask, ancestor and leaf predicates, host feature reports, and decoder results for two deterministic fills of the variable bits. Apple reports some optional features under `hw.optional.arm.FEAT_*`. Missing sysctls are recorded as null. Fills can select reserved operands or overlap other records. Privilege checks, execution state, feature combinations and operand constraints can further restrict a word. The full Arm catalog includes privileged code and multiple extensions beyond any one macOS EL0 profile.

The optional fixture corpus assembles the repository’s interpreter assembly sources and the five existing scalar FP comparison configurations. Binary entries inspect the selected ARM slice of `__text`. Embedded data, unreachable paths, and deliberate traps can all occur there. The static decoder uses a fixed PC and empty import/stub maps. A `typed-ir` row carries a typed opcode candidate; `translated-ir` carries generated lowering statements. Runtime block formation determines the selected GPU path. `rejected` means this decoder threw; process execution handles some words, including BRK and UDF, as guest traps. Static counts describe the recorded words and configurations. No ISA conformance percentage is derived.

## Native and Metal execution probes

Use a runtime and metallib built from the revision under test. Specify a new directory for each run.

```sh
python3 tools/inventory/a64_probes.py --runtime .build/cpp/arm64-metal \
  --library .build/cpp/interpreter/runtime-interpreter.metallib \
  --output /tmp/a64-probes-run-1
```

Shared test machines can supply `--gpulock /path/to/gpulock --slots 2`. The probe tool records one arithmetic result byte from each straight-line fixture, native status, translated status, AOT-enabled status, raw GPU traces, and runtime/metallib hashes. Each assembly source labels the measured instruction. Replacing only that instruction with NOP must yield a different normal native exit before the tool runs the guest. An AOT match gains typed evidence only when the trace includes that instruction’s PC in a typed packet and a single interpreter dispatch covers the path. An unsupported-instruction result must name the specimen’s actual word. Compilation errors, native mismatches, timeouts and unrelated runtime failures remain unmeasured for that instruction. ADDS is the required native/typed positive control. The permanently undefined UDF instruction must deliver SIGILL natively and in both GPU modes. The tool exits successfully when both controls and artifact identity checks pass; examine every row in `summary.json` for individual outcomes.

A passing low-byte result establishes the exercised operand values and observation only. Other operands, lanes, exceptions, flags and memory ordering need their own oracles.
