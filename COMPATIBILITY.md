## Differential decision order

1. Establish the native positive and assert output, errors, status, side effects, and raw returncode in the fixture itself.
2. Run the matching Metal case with a bounded timeout and frozen runtime; preserve each stream/status and boundary trace separately. A guest negative is meaningful only if its native positive control ran and passed.
3. If a contract fails, localize the first divergent service/instruction from the trace; keep a small reusable fixture before replaying an unchanged binary.
4. After contract gates, choose one representative unchanged holdout whose first dependency overlaps a validated boundary. Increase its input or thread complexity only after its smallest control passes; decompression is one useful workload family, not a required example list or gate prerequisite.
5. Then qualify startup/cache/framework clients, JNI/JVM, and GUI independently. Record red, intentional architectural exclusion, and unverified separately; a later pass supersedes only the exact case/runtime it reruns.

## Pointer-signing and parent context

Address-diverse signed pointers are context-sensitive: preserve the guest pointer, key, modifier, and storage/parent address used to sign; do not treat a signed child value as interchangeable with the same raw address or with a token signed for another parent slot. The current runtime models selected authenticated pointers in software (token bucket plus guest address/modifier), not Apple hardware PAC. `LEDGER.md` records specific positive evidence for address-diversified stack probes and signed callbacks, plus selected wrong-key/modifier/unsigned negatives; each remains fixture-scoped. For a new pointer path, compare signed value, authentication result, and failure behavior using the exact parent/storage context on native and Metal.
